# Codemagic App Store signing

## Active signing mode

The owner selected Codemagic Code signing identities. The workflow selects stored
signing files with environment.ios_signing, distribution_type app_store and
bundle_identifier com.bibi.quadratic. Codemagic installs the matching certificate
and provisioning profile before scripts. The Set up App Store signing script
checks those files with scripts/ensure_app_store_profile.py before applying the
exact verified profile with xcode-project use-profiles from BibiApp.
APPLE_TEAM_ID is pinned to 93BX5X327N; generated export options use that teamID
and Archive receives the same DEVELOPMENT_TEAM override. The owner confirmed
that com.bibi.quadratic belongs to this team on November 5, 2026.

The workflow no longer references the bibi_signing environment group or the
CERTIFICATE_PRIVATE_KEY environment variable. Script-based keychain initialization,
certificate import and fetch-signing-files --create were removed. No automatic
certificate creation or revocation runs in the workflow. Private signing material
is still required inside the uploaded certificate package; this mode delegates
its secure management to Codemagic instead of a PEM environment variable.

## Production push profile repair

Build 21's archive log confirms that the stored Bibi profile lacks Push
Notifications and aps-environment. The repair is restricted to com.bibi.quadratic
and its confirmed team 93BX5X327N. A valid installed production-push profile is
reused. Otherwise the helper uses the existing Bibi API integration to look up
the exact App ID, enable only Push Notifications, and reuse or create an App
Store profile tied to the already installed distribution certificate/private key.
It does not create, export or revoke a certificate or register another Bundle ID.
Missing API permissions fail the signing step before Archive.

The selected profile must pass team, Bundle ID, expiration, App Store type,
usable signing identity and production APNs checks. The UUID-named profile is
installed in Xcode's UserData/Provisioning Profiles directory. The build applies only
build/signing/Bibi-AppStore-Push.mobileprovision and retains that public profile
and a sanitized profile-summary.json as artifacts. After a successful repair,
fetch the new Bibi App Store Push profile into Codemagic Code signing identities.
No new environment group or certificate private-key variable is required.

The bibi-ios-signing-validation workflow shares the build configuration but has
an empty publishing section. Use it to verify Archive/export without uploading
an IPA to App Store Connect or sending publishing notifications.

## Configure the certificate in Codemagic

Use a team administrator account and select the Codemagic team owning Bibi.
Open Team settings > codemagic.yaml settings > Code signing identities >
iOS certificates.

- Preferred: upload an existing Apple Distribution certificate as a .p12 package
  containing its corresponding private key. Enter the .p12 password if protected,
  choose a unique reference name such as bibi_distribution, and save it.
- On the Mac holding that certificate, Keychain Access > My Certificates should
  show the certificate with an expandable private key. Export the certificate
  together with that key as Personal Information Exchange (.p12). A .cer file
  without its private key cannot sign an application.
- For a certificate previously generated by Codemagic, Fetch certificate can
  retrieve it through the selected Developer Portal integration. Codemagic cannot
  fetch the private key for an arbitrary certificate created elsewhere.
- If no usable distribution certificate exists, Generate certificate can create
  an Apple Distribution certificate using the intended API integration. Download
  the generated package/password immediately, then follow the UI upload process.
  This is an alternative to reusing an existing certificate, not a requirement
  to create a new one. Respect Apple's certificate limit; do not revoke unrelated
  signing credentials to make room without the owner's approval.

The certificate must be valid, unrevoked and belong to team 93BX5X327N.
Do not put certificate packages, passwords or private keys in Git or chat.
Reference names are labels in the UI; the workflow selects by bundle/type,
so it does not require the illustrative reference name above.

## Configure the provisioning profile

In the same Code signing identities area, open iOS provisioning profiles.

If the correct profile already exists in Apple Developer, choose Fetch profiles,
select the App Store profile for com.bibi.quadratic, give it a unique reference
name such as bibi_app_store, and choose Download selected. Alternatively upload
its .mobileprovision file using Add profile.

If no matching profile exists, use Apple Developer > Certificates, Identifiers &
Profiles > Profiles > Add. Choose the App Store Connect distribution profile
option, select the explicit App ID com.bibi.quadratic and the exact Apple
Distribution certificate uploaded to Codemagic. Generate/download the profile
and upload it to Codemagic. Ensure the App ID exists in the selected team first;
an old profile cannot be retargeted just by renaming its file.

Before retrying, confirm all of these in the profile's displayed metadata:

| Field | Required value |
| --- | --- |
| Type | App Store, not Development or Ad Hoc |
| Bundle ID | com.bibi.quadratic |
| Team | 93BX5X327N |
| Expiration | Future date; profile and certificate both valid |
| Certificate | Matching uploaded certificate, shown with a green checkmark |
| Push entitlement | aps-environment = production |

If the profile names another certificate, regenerate it using the uploaded
certificate or upload the matching certificate/private-key package. A green
profile/certificate pairing is required even though the separate API integration
can authenticate. Capability, App ID or certificate changes may require a newly
generated profile and a fresh upload/fetch into Code signing identities.
